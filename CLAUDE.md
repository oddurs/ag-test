# Working in this repository

`agt` is a Rust testing framework. Read [docs/01-concept.md](docs/01-concept.md)
before making design decisions — the framework has a thesis, and changes that
contradict it need to argue with it rather than around it.

## Attribution: none, ever

No tool, model or assistant attribution appears anywhere in this repository.
Not in commit messages, not in trailers, not in code comments, not in PR bodies,
not in documentation.

Specifically prohibited:

- `Co-Authored-By:` trailers naming any tool, model, assistant or bot
- "Generated with …", "Generated by …", "Co-authored with …" footers
- robot emoji sign-offs
- links back to the tool that produced a change

Commits are authored by the human who owns the repository. The work stands on
its own.

This is enforced in three places — `.githooks/commit-msg` strips it,
`.githooks/pre-commit` blocks it in staged content, and CI re-checks the full
history. Do not attempt to work around any of them; fix the message instead.

## The gate

Nothing ships without:

```bash
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test --all
shellcheck -x -s bash bin/agent lib/*.sh scripts/*.sh .githooks/*
```

That is `AGENT_VERIFY_CMD` plus the shell lint. Run it before proposing a
change, not after.

## Shell code

`bin/agent`, `lib/`, `scripts/` and `.githooks/` must run on **bash 3.2** —
stock macOS. No `wait -n`, no associative arrays, no `${var,,}`, no `mapfile`.
Use `xargs -P` for parallelism. Everything passes `shellcheck`.

## Rust code

- `#![forbid(unsafe_code)]`, `missing_docs` is a warning and treated as an error
  in CI.
- Public types carry doc comments that explain *why the type exists*, not what
  its fields are named.
- Tests are named as sentences describing the claim
  (`derived_seeds_are_stable_and_distinct`), because in this project the test
  name is part of the evidence record an agent reads.
- Keep `agt-core` dependency-light. The wire format should be consumable without
  pulling in a runtime.

## Working in parallel

Use the worktree harness rather than editing the main checkout directly:

```bash
./bin/agent auto <task-name> "<prompt>"
```

See [docs/workflow.md](docs/workflow.md).
